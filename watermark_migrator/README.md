# watermark_migrator

Разовый инструмент: полностью зеркалирует исходный Telegram-канал в целевой
(видео, фото, голосовые, файлы, текстовые посты — всё, в том же порядке), но
для видео сначала находит и убирает статичный водяной знак (плашка
`@vsefrm`). Видео без знака и весь остальной контент копируются как есть, без
перекодирования.

Работает как обычный пользователь (через ваш Telegram-аккаунт, Telethon), а
не как бот — потому что читать чужую историю канала и постить в свой без
прав администратора бот-аккаунтом нельзя.

## Требования к окружению

- Python 3.10+
- `ffmpeg`/`ffprobe` собранные с поддержкой `--enable-nvenc` и `--enable-cuda`
  (для GPU-режима). Если такой сборки нет — поставьте `USE_GPU=0`, тогда
  используется `libx264` на CPU (намного медленнее на многочасовых видео).
- Для GPU-режима — NVIDIA-драйвер с NVENC/NVDEC на арендованной машине.

## Установка

```bash
pip install -r watermark_migrator/requirements.txt
cp watermark_migrator/.env.example watermark_migrator/.env
```

Заполните `.env`:
- `API_ID` / `API_HASH` — с https://my.telegram.org (API development tools).
- `SOURCE_CHANNEL` / `TARGET_CHANNEL` — `@username`, ссылка-приглашение или id канала.
- `WATERMARK_TEMPLATES_DIR` — папка `watermark_migrator/templates/`, в которую
  можно положить сразу несколько чистых, плотно обрезанных кропов плашки
  водяного знака (разные размеры/варианты) — детектор пробует каждый эталон
  на каждом сэмпл-кадре на всех масштабах и берёт лучшее совпадение. Для
  слабозаметных/полупрозрачных знаков перед сравнением автоматически
  усиливается контраст (CLAHE), это помогает находить и почти сливающиеся
  с фоном варианты.
- `BRAND_TERMS_PATH` — `watermark_migrator/brand_terms.txt`, список фраз
  (`@vsefrm`, `Форум ВСЕ` и т.п., по одной на строку, регистр не важен).
  Если фраза встречается **в тексте поста** — она вырезается, текст вокруг
  остаётся. Если фраза встречается **в имени файла** — итоговое имя файла
  при заливке становится `Prime Sector.<расширение>` (расширение берётся от
  реального типа файла, а не всегда `.mp4` — исключение: если видео было
  очищено от знака, оно в любом случае пересохранено как `.mp4`, поэтому и
  имя файла получит это расширение). Список можно дополнять вручную в любой
  момент, без правки кода.
- `OVERLAY_IMAGE` — путь к PNG (с прозрачным фоном), который накладывается на
  найденный водяной знак вместо текста из `MASK_TEXT`. Картинка масштабируется
  под размер найденного знака с сохранением пропорций (не растягивается).
  Чтобы взять готовый стикер из Telegram-стикерпака и сохранить его как такой
  PNG:
  ```bash
  python -m watermark_migrator.fetch_sticker https://t.me/addstickers/НАЗВАНИЕ_ПАКА --index 0
  ```
  (`--index` — какой по счёту стикер в паке, начиная с 0; анимированные
  `.tgs`-стикеры не поддерживаются, нужен статичный). Скрипт скажет, куда
  сохранил файл — впишите этот путь в `OVERLAY_IMAGE`.
  момент, без правки кода.

При первом запуске Telethon один раз спросит номер телефона и код
подтверждения прямо в консоли, затем сохранит session-файл
(`<SESSION_NAME>.session`) рядом — повторный логин не потребуется.

## Запуск

```bash
python -m watermark_migrator.pipeline
```

## Как это работает

1. Список всех сообщений исходного канала загружается один раз (от старых к
   новым) — служебные сообщения (закреп, вступление в канал и т.п.) пропускаются.
2. Для каждого сообщения (с ограниченной параллельностью, `CONCURRENCY` в `.env`):
   - если это видео — скачивание -> вырезка 3 кадров (15%/50%/85% длительности)
     -> поиск плашки через multi-scale template matching (OpenCV) -> если
     найдена, чистка через `ffmpeg delogo` на найденной области (весь ролик
     одним проходом, без ручной нарезки на куски); если не найдена — видео
     идёт в заливку как есть;
   - если это любой другой тип медиа (фото, голосовое, документ) — скачивание
     и заливка без какой-либо обработки;
   - если это текстовый пост без медиа — обработка не требуется, текст просто
     копируется (после вырезания фраз из `brand_terms.txt`).
3. Заливка в целевой канал идёт строго по порядку исходного канала (не по
   порядку завершения обработки), с сохранением подписи/текста.

## Возобновление после сбоя

Прогресс каждого сообщения пишется в SQLite (`state.sqlite3`, путь в
`DB_PATH`). При повторном запуске уже загруженные (`done`) сообщения не
трогаются повторно — можно спокойно перезапускать скрипт после падения без
повторной обработки/заливки готового.

## Настройка скорости/точности

- `CONCURRENCY` — сколько видео обрабатывается параллельно. Упирается в
  число одновременных NVENC-сессий видеокарты, диск и сеть — подбирается
  опытным путём (обычно 2-4 на одну карту потребительского уровня).
- `MATCH_THRESHOLD` — порог уверенности детектора (0-1). Если знак иногда не
  находится — снижайте; если ложно находится на чистых видео — повышайте.
- `SCALE_MIN`/`SCALE_MAX`/`SCALE_STEPS` — диапазон масштабов, в которых
  ищется шаблон относительно референсного изображения.
