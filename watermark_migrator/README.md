# watermark_migrator

Разовый инструмент: проходит по всем видео в исходном Telegram-канале, находит
и убирает статичный водяной знак (плашка `@vsefrm`), и заливает результат в
целевой канал. Видео без знака копируются как есть, без перекодирования.

Работает как обычный пользователь (через ваш Telegram-аккаунт, Telethon), а
не как бот — потому что читать чужую историю канала и постить в свой без
прав администратора бот-аккаунтом нельзя.

## Требования к окружению

- Python 3.10+
- `ffmpeg`/`ffprobe` собранные с поддержкой `--enable-nvenc` и `--enable-cuda`
  (для GPU-режима). Если такой сборки нет — поставьте `USE_GPU=0`, тогда
  используется `libx264` на CPU (намного медленнее на многочасовых видео).
- Для GPU-режима — NVIDIA-драйвер с NVENC/NVDEC на арендованной машине.

## Установка

```bash
pip install -r watermark_migrator/requirements.txt
cp watermark_migrator/.env.example watermark_migrator/.env
```

Заполните `.env`:
- `API_ID` / `API_HASH` — с https://my.telegram.org (API development tools).
- `SOURCE_CHANNEL` / `TARGET_CHANNEL` — `@username`, ссылка-приглашение или id канала.
- `WATERMARK_TEMPLATE` — положите в `watermark_migrator/templates/watermark.png`
  чистый, плотно обрезанный кроп плашки водяного знака (без посторонних
  элементов вокруг) — это шаблон для поиска.

При первом запуске Telethon один раз спросит номер телефона и код
подтверждения прямо в консоли, затем сохранит session-файл
(`<SESSION_NAME>.session`) рядом — повторный логин не потребуется.

## Запуск

```bash
python -m watermark_migrator.pipeline
```

## Как это работает

1. Список всех видео исходного канала загружается один раз (от старых к новым).
2. Для каждого видео (с ограниченной параллельностью, `CONCURRENCY` в `.env`):
   скачивание -> вырезка 3 кадров (15%/50%/85% длительности) -> поиск плашки
   через multi-scale template matching (OpenCV) -> если найдена, чистка через
   `ffmpeg delogo` на найденной области (весь ролик одним проходом, без
   ручной нарезки на куски) -> либо, если знака нет, файл идёт в заливку как есть.
3. Заливка в целевой канал идёт строго по порядку исходного канала (не по
   порядку завершения обработки), с сохранением подписи.

## Возобновление после сбоя

Прогресс каждого сообщения пишется в SQLite (`state.sqlite3`, путь в
`DB_PATH`). При повторном запуске уже загруженные (`done`) сообщения не
трогаются повторно — можно спокойно перезапускать скрипт после падения без
повторной обработки/заливки готового.

## Настройка скорости/точности

- `CONCURRENCY` — сколько видео обрабатывается параллельно. Упирается в
  число одновременных NVENC-сессий видеокарты, диск и сеть — подбирается
  опытным путём (обычно 2-4 на одну карту потребительского уровня).
- `MATCH_THRESHOLD` — порог уверенности детектора (0-1). Если знак иногда не
  находится — снижайте; если ложно находится на чистых видео — повышайте.
- `SCALE_MIN`/`SCALE_MAX`/`SCALE_STEPS` — диапазон масштабов, в которых
  ищется шаблон относительно референсного изображения.
